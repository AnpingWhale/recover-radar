# ADR 0001：原生双进程、共享快照、独立数据适配

日期：2026-10-30。状态：已采纳；日值格式已核对并实现，真实原生登录和签名桌面安装仍待验收。

## 背景

需要维护清晰、可开源的 macOS 五轴恢复雷达。数据来自远程 COROS MCP，WidgetKit 的扩展生命周期与刷新预算受系统管理。

## 决策

1. Swift 6、SwiftUI、WidgetKit，最低 macOS 14；零第三方运行/构建依赖。
2. 一个主 app 与一个 widget extension，使用本地 Swift Package 共用 Core 与 UI。
3. 主 app 完成 OAuth/MCP/计算并独占写入；扩展仅读 App Group 原子 JSON。
4. 主 app Keychain 私有保存 token，不向扩展共享凭证。
5. 使用 30 个完整日的每轴中位数及明确标注的相对显示刻度；不创建综合恢复分。
6. M0 使用合成数据；后续在观察官方服务实际文本后实现严格日值适配和原生 OAuth。测试始终使用合成报告，不把会话中已安装的 COROS 插件当作独立应用运行依赖。

## 原因与取舍

直接在扩展同步会引入认证、超时、重复请求和后台执行问题；只读快照使其行为小且可验证，代价是主 app 不运行时不能获得新数据。菜单栏常驻是明确可选的功能。

原生 Path 足以绘制五轴；无需图表库。小规模日值与快照用 Codable JSON 足够，暂不引入数据库。自实现有限的 COROS 适配降低依赖，但需要覆盖 OAuth、JSON/SSE、错误与服务兼容行为；它不是通用 MCP SDK。

## 重新评估条件

真实服务不支持独立公共客户端、稳定数据输出或必要历史时，先调整产品可用性与缺失展示；不绕过授权、不改用未授权私有接口。历史量或查询需求显著增加时评估 SwiftData。新增数据源时通过 HealthDataSource 扩展，不让服务响应侵入视图。
